# PRD

> 범위: ai-setup 흡수(`2026-10-30-ai-setup-absorption.md` 의 D1~D16). 기존 jarvis 기능(게이트웨이·core 홈·사용량)은 `README.md` 가 설명하며 아직 이 문서에 없다.

## 문제

같은 기기의 같은 Orca 를 ai-setup 과 jarvis 가 서로 다른 형태로 설치·갱신했다. 두 도구가 서로를 피하는 예외가 생겼고(jarvis `0dcf2de`), 기기를 여러 대 운용하는 사용자 한 명이 두 도구의 차이를 기억하고 맞춰야 했다.

## 목표

- jarvis 하나가 기기의 개발 환경(하네스, 훅, 스킬·플러그인·MCP, Orca)을 설치·갱신·점검·제거한다.
- 모든 모듈이 같은 계약(`status`·`plan`·`apply`·`uninstall`)을 따라 core 홈과 부트스트랩이 같은 방법으로 부른다.
- 한 기능은 언제나 한 곳에만 있다. 옮긴 기능은 ai-setup 에서 지운다.
- 원격 작업은 안전한 것만 바로 실행하고, 나머지는 사용자 승인을 받는다.

## 비목표

- 에이전트 리팩토링(하네스, 하위 에이전트, 대화 창구)은 따로 설계한다.
- 영수증 이름·위치는 바꾸지 않는다(기존 설치와의 호환).
- 첫 단계(Orca 시범)에서는 분류기를 쓰지 않는다.

## 범위와 순서

Orca(시범) → doctor → 훅 → 하네스 설치·갱신 → 스킬·플러그인·MCP → 나머지. Orca 시범을 마친 뒤 순서를 다시 확인한다.
