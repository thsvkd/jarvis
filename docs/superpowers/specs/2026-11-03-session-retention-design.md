# 로컬 채팅 세션 보존 기간

## 목표와 범위

Jarvis setup에서 Claude Code의 로컬 대화 기록을 장기간 보존하도록 계획하고 적용한다. 대상은 기기별 Claude Code 설정이며, 서버 측 보존 정책, 이미 삭제된 기록의 복구, 별도 백업은 범위 밖이다. Codex는 공식적으로 지원되는 전체 세션 보존 기간 설정을 확인하지 못했으므로 임의의 설정이나 파일 조작을 하지 않고 확인 불가로 표시한다.

## 방식

선택한 방식은 Claude의 공식 `cleanupPeriodDays`를 사용하는 것이다. Jarvis가 관리하는 기본 목표는 36,500일(약 100년)이다. 공식 문서는 정수 일수를 지원하고 긴 기간의 예를 들지만 최대값은 명시하지 않으므로, 이 값이 대상 버전에서 유효하게 읽히는지 검증하고 무제한이라고 부르지 않는다. 대안인 세션 파일의 별도 백업은 저장 공간과 복원 관리가 추가되어 선택하지 않았다.

## 동작

- setup plan은 `~/.claude/settings.json`의 해당 항목이 없을 때만 36,500일 설정을 `config` 단계로 보여 준다. 이미 사용자 값이 있으면 변경하지 않고 현재 값과 적용하지 않은 이유를 보고한다. 기존 값의 길고 짧음이나 유효하지 않은 값도 임의로 고치지 않는다.
- plan과 status는 읽기 전용이다. 계획은 대상 설정의 현재 상태와 적용할 워커를 식별하도록 봉인하고, apply와 파일 교체 직전에 다시 확인해 변경을 감지하면 덮어쓰지 않는다. 비협조적 외부 프로세스의 쓰기는 마지막 확인과 교체 사이에 발생할 수 있어 원자적 보장은 불가능하다. JSON을 읽을 수 없거나 예상하지 못한 파일 형태이면 쓰지 않고 실패를 알린다.
- 적용은 다른 설정과 영수증 키를 보존하고 기존 파일을 백업하며, 임시 파일과 교체를 이용한다. Jarvis가 추가한 값의 소유권을 영수증에 기록한다. 다시 적용은 멱등이고 사용자가 이후 값을 수정하면 그대로 둔다.
- uninstall은 영수증에 기록된 값이 현재 값과 같을 때만 해당 키를 제거한다. 사용자가 수정한 값과 영수증을 보존하면 deferred로 보고한다. 기존의 plan_id 및 제거 계약을 따른다.
- status 또는 plan에 Claude 설정의 상태와 Codex의 미확인 상태를 구분해 표시한다. 사용자 설정과 상위 우선순위 설정이 다를 수 있으므로 설정 파일 기록만으로 실제 유효 설정이 확정됐다고 주장하지 않는다.

## 수용 기준

- WHEN Claude 설정에 해당 키가 없고 승인한 setup plan을 적용하면 THE SYSTEM SHALL 다른 설정을 보존하며 `cleanupPeriodDays`를 36,500으로 추가하고 소유권을 기록한다.
- WHEN 기존 키가 있거나 적용 전 파일이 바뀌거나 JSON이 잘못되면 THE SYSTEM SHALL 그 설정을 덮어쓰지 않고 그 이유를 보고한다.
- WHEN status·plan 또는 uninstall dry-run을 실행하면 THE SYSTEM SHALL 설정과 영수증을 쓰지 않는다.
- WHEN 동일한 설정을 재적용하거나 제거하면 THE SYSTEM SHALL 멱등으로 동작하며 제거 시 Jarvis가 추가한 값이 그대로인 경우에만 그 키를 제거한다.
- WHEN Codex의 보존 상태를 표시하면 THE SYSTEM SHALL 지원하지 않는 무제한 보존을 주장하거나 임의 설정을 쓰지 않는다.
- 임시 홈 단위 테스트로 위 조건과 기존 setup 계약을 검증한다. 실제 홈이나 다른 기기를 자동 테스트에 사용하지 않는다.
