# CODE_STYLE

## 원칙

- 주변 코드처럼 쓴다. 기존 파일의 네이밍·구조·오류 처리 방식을 먼저 읽고 따른다. 스타일 개선은 요청받았을 때만 한다.

## 스크립트 구조

- 스크립트 파일은 {root}/scripts/ 아래에 작성.
- 스크립트 파일은 다음과 같은 카테고리등을 가진다.
  - `setup` — 설치·설정 관련 스크립트
  - `run`, `serve` — 실행 관련 스크립트
  - `test` — 테스트 관련 스크립트
  - `lint` — 린트, 포매팅 관련 스크립트
  - `deploy`, `publish` — 배포, 게시 관련 스크립트
  - `_lib`, `_common` or `utils\`, `helpers\` — 라이브러리, 유틸리티, 헬퍼 스크립트 파일 or 폴더. 유틸, 헬퍼, 라이브러리 파일 수가 많을 때만 폴더를 만들 것.
  - 이외 필요에 따라 적절하게 스크립트 파일을 작성, 분류.

## 주석

- "무엇"이 아니라 "왜"를 쓴다. 코드가 이미 말하는 것을 반복하지 않는다.
- 우회·제약·놀라운 선택에는 이유를 남긴다. 그 줄이 나중에 지워지는 것을 막는 것은 주석뿐이다.
- 죽은 코드를 주석으로 남기지 않는다. 히스토리가 보관한다.
- 너무 길게 작성하여 읽기 어렵게 만들지 않는다.
- 적절한 docstring 형식을 채택할 것.

## 언어별 설정

- `<언어>`: `<이 저장소만의 규칙. 없으면 이 절을 지운다>`
