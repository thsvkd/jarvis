범례 · 공개 상태를 읽는 법

선 색 = 들어오는 길의 종류

  • 공개인터넷 누구나. 인터넷 → Cloudflare 엣지 → cloudflared 터널 → Caddy :80 → 앱
  • Tailnet내 tailnet 기기만. *.<도메인> → 이 기기의 tailnet IP → Caddy :443. 터널로 오면 404
  • LAN 직접Caddy 를 거치지 않고 이 기기 포트로 바로. 같은 공유기(와 tailnet) 안에서만
  • 의존앱 → 내부 백엔드(DB·캐시). 밖으로는 열리지 않음

왼쪽 위 공개 상태 = 서비스마다 가장 넓게 열린 범위 하나로 센 수

  • 공개인터넷 누구나
  • LAN같은 공유기 안 누구나
  • Tailnet 전용내 tailnet 기기만
  • 로컬이 기기 안에서만

노드 색·모양 = 서비스 상태 (저하·다운으로 가는 선은 끝에 상태 점)

  • 정상
  • 저하
  • 다운
  • 확인 불가

흐르는 점 = 최근 1시간 요청(가장 많은 길 몇 개). 점이 많고 빠를수록 많습니다 — 한동안 손대지 않으면 멈춰요. 점선 테두리 = 이 기기 안. 가는 선 줄기 = 같은 관문에서 갈라지는 길.

상자 = 포함 관계(그 안에서 돈다)

  • 기기(실선 상자) · 인터페이스이 기기 — 실제 기기. 테두리의 칩이 인터페이스: 위 eth0·wlan0 은 LAN 으로, 아래 tailscale0 은 Tailnet 으로. 제목의 기호와 말이 기기 상태예요(▲ 주의 · 까닭)
  • Docker 엔진 ⊃ 도커 네트워크 ⊃ 컨테이너상자 머리의 172.x.0.0/16 이 서브넷. 점선 묶음(host 네트워크·호스트 프로세스)은 논리적 묶음이에요
  • ↗ 다른 망에서 붙은 컨테이너본래 망은 ↗ 뒤의 이름. 누르면 그 컨테이너로
  • 원격 기기다른 tailnet 기기. 같은 기기 안의 노드는 그 카드 안에 그려요(예: 서버 안의 Tailscale 사이드카 컨테이너)

선 = 실제 연결(색과 무늬를 함께 봐요)

  • 유선속도는 인터페이스 칩에
  • 무선신호 dBm 은 칩에
  • 업링크 ↑공유기 NAT → 인터넷 (겹선)
  • 같은 LAN같은 공유기 아래 기기
  • 오버레이 ◈tailscale0 → Tailnet (굵은 선)
  • Tailnet 직결P2P 로 오가는 중
  • Tailnet 중계DERP 서버를 거쳐 오가는 중
  • Tailnet 유휴온라인, 지금 오가는 연결 없음
  • 오프라인한 줄로 묶음
  • 터널QUIC 연결 수
  • 엣지Cloudflare ↔ 인터넷
  • 다른 망에도 붙음끝 점 = 그 망의 머리
  • 바인딩그 인터페이스에만 연 포트
  • 열린 포트가리킬 때만 · 칩 → 인터페이스

칩 왼쪽 띠 = 그 칩이 돌리는 서비스의 카테고리

  • 공개
  • Tailnet 전용
  • 호스트 서버
  • 내부 백엔드
  • 인프라
  • 시스템 데몬

칩·카드의 기호 = 상태

  • 정상
  • 저하 · 주의
  • 다운 · 장애
  • 확인 불가·오프라인

청록 포트 번호 = tailscale0 에만 바인딩된 포트. 선 위 알약 = 경로(직결·중계·유휴)·QUIC 연결 수·NAT. 한 가지 값은 한 곳에만 적어요.
